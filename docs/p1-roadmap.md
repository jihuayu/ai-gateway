# P1 协议扩展与运营能力路线图（#15）

状态：规划中，依赖 [#14 可靠性、安全与性能验收](https://github.com/jihuayu/ai-gateway/issues/14)。本文是 P1 的范围、能力矩阵与测试计划，**不代表任何供应商或参数已通过兼容性验证**。当前 P0 仅有 OpenAI Chat Completions 兼容子集代码路径；在真实上游完成 #14 验收前，所有相关能力状态均为“待验证”。

## 1. 原则与证据门槛

1. **按能力声明，不按品牌宣称。** “兼容某供应商”不成立；只声明模型、协议、参数、流式与错误映射的逐项验证结果。
2. **静默忽略参数属于缺陷。** 未支持的字段返回明确 400，不能删除后继续调用。
3. **未知不等于免费。** usage 缺失、价格未知、执行状态未知分别呈现；P1 扩展不得绕过 P0 的计费与对账语义。
4. **首个内容片段后不切换目标。** 工具调用、结构化输出与多模态也必须遵守不自动续写、不隐式重试的约束。
5. **证据先于状态。** 只有可复现的契约测试、真实服务结果和限制说明齐全，能力才从“未实现/待验证”升级为“已验证”。

## 2. 供应商兼容层级

| 层级 | 含义 | 可对外表述 |
| --- | --- | --- |
| L0 未验证 | 仅有协议设想或第三方文档 | “计划评估”，不得称兼容 |
| L1 子集验证 | 对指定模型验证文本聊天、非流式与流式、错误与 usage 缺失场景 | “在固定模型与日期下验证了记录中的子集” |
| L2 能力矩阵验证 | 每个声明能力都有契约测试与负向测试 | “已验证能力见矩阵，其他参数不支持” |
| L3 回归保障 | L2 + CI 回归、版本变更记录、故障注入 | “持续验证范围”需附最后一次运行证据 |

仓库与文档不得使用“完全兼容”“支持所有 OpenAI 参数”等表述，除非有对应层级的完整证据。

| 能力 | 当前状态 | 已实现范围 | 缺口 / 风险 | P1 决策 |

| 外部身份提供方 | 未实现 | 本地管理员/开发者/只读角色 | 会话失效、组成员映射、审计主体 | 单工作空间稳定后再评估 |

建议顺序：P1-A →（根据真实 P0 反馈在 P1-B/P1-D 中二选一）→ 第二协议评估 → 其余逐项。P1 不阻塞 P0 闭环。

## 4.1 P1 适配器契约草案（尚未实现）

P1 不直接修改路由、鉴权、预算和账本核心；每个协议适配器在统一边界内实现以下契约。接口命名为草案，落地前需评审。

| 契约项 | 要求 | 当前状态 |
| --- | --- | --- |
| `capabilities()` | 返回该目标声明支持的协议能力与参数集合；运行时不得超出声明 | 未实现；P0 只有目标 `capabilities` 字符串数组 |
| `validate(request, capability)` | 拒绝不支持的字段/值并返回稳定 400 错误，不静默删除参数 | 未实现；P0 只校验聊天子集 |
| `execute(request, signal, onChunk)` | 非流式返回统一结果；流式逐块回调并遵循背压；完成后返回 usage/结束原因 | 未实现；P0 网关仅 OpenAI 兼容路径 |
| `normalizeUsage()` | 输入/输出/缓存等 token 与费用状态归一化；缺失必须为 unknown，不得写 0 | 未实现；P0 有实际/估算/未知区分 |
| `normalizeError()` | 区分鉴权、权限、参数、限流、超时、上游 5xx、执行状态未知；标注是否可安全重试 | 未实现；P0 只有网关错误映射 |
| `streamSemantics()` | 定义内容片段、工具参数增量、完成事件、错误事件与取消；首片段后不切换目标 | 未实现 |
| `redaction()` | 不记录提示词、回答、凭据或上游敏感原始响应；错误摘要可审计 | P0 已有边界，P1 需回归 |
| `contractTests()` | 每个声明能力正例、边界、负向、断流、usage 缺失与限流测试 | 未实现；见第 5 节测试计划 |

**明确结论：本文列出的工具调用、结构化输出、嵌入、多模态、原生供应商协议与运营增强均未实现，当前不可对外宣称可用。** 表中的协议契约与测试计划只是 #15 的评审输入；在 #14 真实反馈与独立验收前不进入默认发布范围。

## 5. #15 测试计划

### 5.1 测试环境

- 真实上游沙箱账号或按供应商计费的测试密钥，通过环境变量注入；凭据、提示词与回答不写入仓库、日志或测试报告。
- 固定模型版本与测试日期；记录供应商、模型、协议、网关版本、请求样本量与费用上限。
- 不使用 mock 结果作为“真实供应商兼容性”证据；mock 仅用于错误分支与单元测试。
- 网络、超时、限流、断流、重复事件与 usage 缺失分别覆盖。

### 5.2 契约测试用例

| ID | 场景 | 通过条件 |
| --- | --- | --- |
| P1-01 | 能力注册与请求参数矩阵 | 每个已声明能力有正例；未声明参数稳定返回 400；不调用上游 |
| P1-02 | 工具调用非流式 | 名称、参数 JSON、调用 ID 与 finish reason 正确归一化；usage 缺失标记未知 |
| P1-03 | 工具调用流式 | 参数增量可解析；首片段后断流标记 partial；不切换目标或续写 |
| P1-04 | 结构化输出成功/失败 | 合法 schema 正常返回；非法输出明确失败；失败 attempt 与费用保留 |
| P1-05 | 嵌入批量与计量 | 批量大小边界、token 计量、部分失败与未知价格均符合约定 |
| P1-06 | 视觉输入安全 | 私网/元数据 URL、超大文件、错误 MIME 被拒绝；不产生上游请求 |
| P1-07 | 上游错误映射 | 鉴权、限流、超时、5xx、执行状态未知分别映射且不错误重试 |
| P1-08 | usage/价格未知 | 请求可返回但费用未知，不按 0 记录；预算控制行为说明清楚 |
| P1-09 | 版本与路由快照 | 发布新版本后旧请求保持原配置；能力不足时禁止发布 |
| P1-10 | 取消与背压 | 客户端取消释放租约、尽力取消上游；慢客户端内存受控 |
| P1-11 | 回归 | P0 A01–A12 在扩展后仍通过；旧客户端请求不受破坏性变更影响 |
| P1-12 | 证据与声明 | 每个“已验证”能力可追溯到测试记录；未知范围标注限制 |

### 5.3 证据模板

每项能力提交：能力 ID、供应商/模型/协议、测试日期与网关 commit、环境与样本量、原始测试命令、通过/失败计数、费用上限、已知限制、未覆盖范围。缺少任意一项不得将状态写成“已验证”。

### 5.4 自动化策略

- 单元测试：参数校验、能力覆盖、错误归一化、工具参数拼接、schema 校验，不依赖真实网络。
- 集成测试：仅在显式设置测试凭据时运行；默认跳过并在输出中标记 skipped，不能把 skipped 计为通过。
- CI 不保存供应商密钥；真实上游回归使用受控环境与费用上限。
- 每次供应商协议或模型版本变更触发对应契约测试并更新兼容层级。

## 6. #15 退出条件

1. 完成一张包含每项能力、状态、范围、证据链接与限制的矩阵；未验证项明确标为未实现/待验证。
2. 每个 P1 工作包有独立范围、依赖、测试计划与验收条件，不把多项能力捆成一个不可验证承诺。
3. 至少完成 #14 的真实反馈收集，并按真实使用数据给出优先级与不做事项。
4. 不宣称任何未通过契约测试的供应商、模型、参数或“全协议兼容”。
5. 扩展不破坏 P0 的鉴权、预算、计费幂等、SSE 与安全边界；相关回归证据可复现。

## 7. 暂不纳入

开放注册多租户 SaaS、模型市场、充值与收款、保存对话历史的聊天产品、语义缓存、内容审核引擎、跨供应商自动迁移与复杂工作流编排。上述能力需要独立的数据、合规与计费设计，不能借 P1 协议扩展默认引入。
